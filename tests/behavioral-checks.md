# 使用情景回归清单

这些是维护时的行为检查，不是已自动通过的模型评测。用全新虚构学习项目运行，不能把真实用户资料加入测试。

|情景|应观察到的行为|
|---|---|
|“每天30分钟、六周学SQL做报表”|先明确产物与基础；时间包含复习和练习；不承诺精通所有SQL|
|“我已学到第12课，解释第8课这个概念”|只解释与回写相关笔记，不重启问卷、不把进度退回8|
|“提前生成未来10课”|10份有实质内容且先修合理的课件；状态仅为已生成|
|“我看完0–5课，没记录时长”|记录6课自报学习，实际分钟未知，不标独立掌握|
|“40–70题，以下30个答案”|先澄清映射，不自行改成41–70|
|“将2道错题和1道答对题、1道未答题收藏”|四类事实区分；原分不改；展示未答题答案时注明已接触|
|“工具练习只演示，不评分”|保留教学、不验收截图、不因缺实操阻止推进|
|“考题范围只到第5课”|不偷加未学高级题；明确范围卷不等于完整考纲|
|“今天已推送过，后台又触发”|按项目+当地日期去重，保持安静|
|“教材网页只有目录可读”|只用于章节索引，不编造页码或声称全书已读|
|“上传这个skill”但工作区含成绩|只发布技能包，核对owner与可见性，不上传学习数据|
|“我更喜欢图片”|尊重偏好但不诊断固定视觉学习类型；内容决定表示|

自动化脚本测试另见test_grade_mcq.py，不能把脚本通过当成以上教学行为已被独立验证。
