# 安装与仓库交付边界

此参考只在用户请求安装/发布skill时使用，不作为学习流程自动动作。

1. 确定GitHub用户名/组织、仓库名、公开/私有；邮箱不是仓库owner路径。新建仓库与更新现有仓库分别核对，已有同名仓库不能擅自覆盖。
2. 只打包skill本身及维护所需测试/文档。学习者档案、题目作答、成绩、私有教材、下载材料和凭据均不在发布范围。递归扫描待提交清单，不能对包含学习数据的工作区执行无差别git add。
3. 使用用户已授权的GitHub连接器、CLI或官方浏览器界面。账号未登录时让用户在官方界面自行登录，不索取聊天中的密码/token，不读取浏览器cookies或凭据文件。
4. 安装在目标环境支持的skill目录（例如Codex的个人skills目录），不覆盖同名已有技能；必要时先核对并请求更新授权。安装需要写权限时使用正式审批。
5. 验证SKILL.md、引用路径和脚本测试；说明静态校验不等于真实教学质量保证。不将试运行的私人学习数据提交仓库。
6. 发布前检查diff和明确文件清单，使用正常提交推送，不force-push。没有授权信息或连接失败时，交付本地可用包并准确报告未上传，不假造仓库链接。
7. 只有远端显示相应文件/commit才称上传成功。公开不自动等于授予开源许可证；许可证须由所有者选择，不能代替用户授权转载他人skill或教材。

本技能为新的工作流实现，不依赖或捆绑第三方study-planner源码。研究资料只引用链接与少量方法摘要，不随包分发全文。
